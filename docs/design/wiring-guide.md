# Wiring guide — prototype → production (Prompts 7–13)

How each screen moves from `/design/demo/**` to a real route. Every screen
keeps the same shape it has today: **server container page** (guard → port
implementation over the DB → props) feeding the **same view component**
that the demo renders. The views are already written; prompts 7–13 write
containers + server actions and swap `world` slices for queries.

Conventions for every wiring task:

- **Guard first**, outside `<Suspense>` (`requireRole`/`requireStaff`/
  `requireVerifiedAlumni` as applicable), matching the ROUTE_POLICY entry.
- **Port implementation**: each feature folder has `ports.ts`. Implement it
  in `src/server/services/<feature>.ts` with explicit column lists (never
  `SELECT *`), parameterised queries, and the query budgets below.
- **Actions**: `defineAction` wrappers in `src/lib/actions/<feature>.ts`
  (same shape as `staff.ts`/`departments.ts`/`account.ts` — Zod input →
  policy check → service in `withTransaction` → audit → `ActionResult`).
- **Audit**: every data-changing action writes an audit row in the same
  transaction (see `src/server/audit` action union — extend it when adding
  new actions).
- **Neutral errors**: anything touching account enumeration or existence
  (register, verify, tokens) returns identical user-facing output for
  hit/miss — already the rule in `server/services/account.ts`.
- **Route policy**: add the `RoutePolicyEntry` before shipping the route
  (the completeness test fails otherwise); regenerate the authz matrix.
- **View-models**: snake_case row → camelCase VM mapping lives at the top
  of each service file — keep it one place per feature.

## Neutral-error and privacy rules to preserve when wiring

- Register + resend + forgot/reset/set + verify: identical response
  regardless of existence — already the service contract.
- `/verify/[token]`: minimal fields; invalid token → same 404 as unknown.
- Directory opt-in fields (`showEmail/showPhone/directoryVisible`)
  decide what the alumni-facing directory may show; admin sees all.
- Export honours the same filters as the list; viewer can never export
  (D9). All exports write `export.downloaded` audit rows.
- Every admin write is audited in-transaction; audit metadata is
  sanitized by the existing helpers (no secrets, ≤4 KB).

## Query-budget reference (context.md §7)

- Typical page ≤ 5 queries, parallelised (`Promise.all` in container).
- Lists: server-side pagination (≤100 rows, hard cap 500 export chunks).
- Filter options + analytics: cached 30–60 s server-side.
- Dev `DB_QUERY_STATS` counter must stay green on every wired page.
